# Полный Markdown-экспорт MSFS

Требуются Python 3 и Pandoc (`brew install pandoc` на macOS).

```sh
python3 scripts/build-markdown.py
python3 scripts/build-markdown.py --language en
python3 scripts/build-markdown.py --output-dir /absolute/path/to/attachments
```

По умолчанию обе языковые версии собираются в `output/markdown/`:

- `msfs-en.md`, `msfs-ru.md` — полные читаемые версии, включая доказательства,
  приложения, библиографию, формулы и исходники рисунков.
- `msfs-en-source.md`, `msfs-ru-source.md` — точные исходные LaTeX-файлы в Markdown
  code fence для проверки конверсии и разбора LLM без потери исходного синтаксиса.
- `msfs-en.manifest.json`, `msfs-ru.manifest.json` — SHA256, размеры, перечень
  меток, библиографических ключей, среды, количества доказательств и формул.

Конверсия идёт через Pandoc AST. Экспортёр восстанавливает исходную общую
нумерацию утверждений внутри разделов (включая буквенные приложения), переносит
аннотацию из метаданных в тело, сохраняет TikZ и подписи рисунков, делает исходные
метки явными ссылками. Неизвестные LaTeX-блоки сохраняются как код; преамбула с
макросами прилагается. Ключи цитирований остаются явными, а полный исходный
`thebibliography` находится в документе. Обычный Markdown-просмотрщик не рисует
TikZ: его исходник предназначен для чтения/анализа, а вид рисунка доступен в PDF.

Сборка проверяет порядок и число всех theorem-сред, число разделов/доказательств,
сохранность математических AST-узлов, меток, библиографических записей и рисунков.
Точная source-версия проверяется обратным побайтным извлечением. Новый внешний
`input/include` или изменённое соглашение о нумерации требует явной адаптации,
а не тихого неполного экспорта. Теоретические исходники и PDF не меняются.
Языковые версии экспортируются как есть: это не операция их согласования.
